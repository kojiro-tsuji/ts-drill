# 問題の作り方（AI 向け手順書）

問題は `problems/<id>.json` に 1 問 1 ファイルで置く。置くだけでアプリに出る（一覧への登録は不要）。

## 手順

1. 既存の問題と重複しないテーマを選ぶ（`problems/` のタイトルを確認）。
2. `problems/<id>.json` を書く。サンプルの `output` は **空文字 `""` のままにする**（AI に計算させない）。
3. `npm run verify -- --write <id>` で模範解答を実行し、`output` を書き込む。
4. 書き込まれた出力が、問題文から想定される答えと一致するか目で確かめる。食い違えば模範解答か問題文が誤り。直して 3 に戻る。
5. `npm run verify` が全問 OK になることを確認する。

## JSON の形

```jsonc
{
  "id": "adjacent-diff-max",          // 英小文字・数字・ハイフン。ファイル名と同じ
  "title": "隣り合う差の最大値",
  "difficulty": 1,                    // 1〜5（下の表）
  "statement": "…せよ。",              // 常体（だ・である調）
  "constraints": ["2 ≤ N ≤ 10⁵", "…"],
  "inputFormat": "N\nA1 A2 … AN",
  "outputFormat": "最大値を 1 行で出力",
  "timeLimitMs": 2000,
  "samples": [{ "input": "5\n3 1 4 1 5", "output": "" }],  // 2〜3 個
  "hiddenTests": [],
  "starterCode": "（標準の雛形。既存の問題からそのまま写す）",
  "solution": {
    "code": "import { readFileSync } from \"fs\";\n…",
    "explanation": [{ "lead": "要点。", "body": "本文。" }]  // 2〜4 個
  }
}
```

## 難易度

| 値 | 表示 | 目安（AtCoder ABC） | 主なテーマ |
|---|---|---|---|
| 1 | 入門 | A 問題 | 入出力、四則演算、条件分岐、単純なループ |
| 2 | 初級 | B 問題 | 配列・文字列の操作、全探索、シミュレーション |
| 3 | 中級 | C 問題 | ソート、二分探索、累積和、貪欲、BFS・DFS の基本、bit 全探索 |
| 4 | 上級 | D 問題 | 動的計画法、ダイクストラ、Union-Find、尺取り法、組合せ（mod） |
| 5 | 最上級 | E〜F 問題 | 発展的な DP、セグメント木・BIT、最小全域木、トポロジカルソート、整数論 |

## 書き方の決まり

- 文体は常体。問題文は「〜せよ。」で終える。
- 数式の添字は `A1`, `A(i+1)` のように書く。上付きは `10⁵` `10⁹` を使う。
- 入力はすべて標準入力から読む（`readFileSync(0, "utf8")`）。使える Node API は `fs.readFileSync` と `console.log`、`process.stdout.write` だけ。
- 出力が複数行になる場合は、配列を `join("\n")` してまとめて出す（速い）。
- 64 bit を超えうる値は `BigInt` を使い、制約にもそれが分かる範囲を書く。剰余は `998244353` か `1000000007`。
- 模範解答は読みやすさ優先。短いコメントで要所を説明し、計算量が制約内に収まること。
- 解説は「太字の要点（lead）＋本文（body）」。最後の 1 つは計算量にする。
- サンプルは境界（最小ケース、答えが 0 や No になるケース）を 1 つ含める。
- 答えが一意に決まる問題だけを作る（複数解を許す問題は、今の判定では扱えない）。
